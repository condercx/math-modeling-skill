# Subagent 与按需复核

Subagent 是可选协作者。项目 `AGENTS.md` 优先；除非用户或项目明确要求，不要为了满足旧 `M1/P1/P2/W1/W2` 流程而暂停主线。

## 何时使用

- 任务复杂、跨文件、结果高风险或最终论文需要额外检查时。
- 用户明确要求独立复核、并行调研或算法原型时。
- 已完成主体工作，希望另开窗口验证证据、代码或文字时。

普通实现、实验和写作可以直接进行。没有安排复核不构成未完成。

## 复核方式

如果决定复核：

- 复核者尽量未参与被审产物编写，默认只读。
- 给复核者输入快照、目标、范围和必要命令。
- 结论用“通过 / 有问题 / 无法判断”表达，并列出证据。
- 问题交回原执行者修正，不要求建立固定回执文件或 Gate 状态机。
- 论文复核时检查 Markdown 格式残留、实际渲染和支撑材料完整性。

`M1/P1/P2/W1/W2` 可以作为快捷标签，例如模型复核、最小运行复核、代码复核、论文证据复核和全文复核，但不具有阻断继续工作的特殊权限。

## 可选协作类型

- 官方规则核验
- 附件和数据盘点
- 文献与模型调研
- 隔离算法原型
- 独立实验批次
- Python/MATLAB 对照
- 术语与英文表达核验

子代理可以返回建议、证据或实验产物；关键模型、参数、结论和最终文稿仍由主 Agent 与队员确认。

## 并行边界

- 不让多个 Agent 同时覆盖同一个 Word 主稿、权威代码文件或结果目录。
- 大型实验使用独立 run 目录，避免互相覆盖。
- 机械检查优先运行已有脚本，不必额外派 Agent。
